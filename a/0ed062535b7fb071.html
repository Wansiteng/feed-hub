AI agent 的下一个障碍：让网站放它们进去

TechCrunch · AI · 评分 7/10：agent 访问网站与反爬对抗，涉及 agent 生态标准，相关且有实质信息
原标题：The next hurdle for AI agents: getting websites to let them in

要点

  • 亚马逊开始屏蔽Meta的Muse AI agent访问其零售网站
  • 沃尔玛与Muse合作，但用户仍因人机验证失败无法完成购买
  • Meta、沃尔玛、Stripe等公司正合作制定AI agent通信开放标准

像 Meta 的 Muse、Instinct、ChatGPT 的 Dots 等个人 AI agent，正在掀起一波新的消费级 AI 浪潮，其功能远不止回答查询。这些 AI agent 实际上可以代表用户完成任务，比如预订机票、预订晚餐、订购杂货等，而用户无需具备足够的技术能力，在自己电脑上设置 OpenClaw 或其他 agent。

但采用这些 agent 的消费者常常遇到问题：请求另一端的网站会阻止 AI 完成任务。

最近，亚马逊开始在其零售网站上屏蔽 Meta 的 Muse AI agent，这意味着该 agent 无法再浏览其产品目录或进行购买。

然而，问题不仅限于亚马逊或 Muse。社交媒体上的用户投诉表明，他们的 agent 经常遇到类似的屏蔽。其中一些是有意为之，比如亚马逊的；另一些则是网站传统的反机器人措施所致，这些措施旨在防范垃圾信息和恶意活动。

最终用户不清楚屏蔽是否是网站所有者的无意之举，这让他们既对服务提供商或零售商感到沮丧，也对试图促成交易的 agent 感到不满。

例如，TechCrunch 在社交媒体上看到一些投诉，声称 Muse 无法在沃尔玛的零售网站上完成购买。（NBC 也报道称，这是沃尔玛在测试该 AI agent 时遇到的问题。）

但沃尔玛的一位发言人告诉我们，这些并非有意为之。事实上，沃尔玛与 Muse 有合作，正如9 月在 Meta 的 Connect 开发者大会上宣布的那样。该公司表示，它希望出现在客户所在的地方，而现在这包括通过 AI agent 体验提供服务。

沃尔玛客户经常遇到的问题（见下文）似乎是，网站会显示一个必须点击的按钮，以验证访客是人类。如果这一过程被打断，验证可能会失败，agent 就会被踢出。

这表明，我们目前用于验证人类身份、保护网站免受垃圾信息和机器人侵扰的技术，可能并不最适合我们正在迈入的 agent 优先的 web 时代。

为了解决这个问题，包括 Meta、沃尔玛、Stripe、Sierra、Genesys、Rocket、NiCE 和 Decagon 在内的行业合作伙伴已开始制定一项开放标准，该标准将规定 AI agent 如何与企业沟通，帮助区分代表用户行事的良性机器人和恶意机器人。Meta 在一篇博客文章中表示，该协议将特别关注出于在线商务目的的 agent 对 agent 通信。

与此同时，消费者的困惑比比皆是。

尽管沃尔玛至少试图通过 AI agent 提供服务，但其他公司对此想法并不那么热衷，或者尚未完全接受这项技术。

例如，机票预订目前是 agent 的主要应用场景之一，但许多人反映，航空公司会拒绝其 agent 的请求。

以达美航空为例，该公司告诉我们，正在采取措施保护客户免受未经授权的自动化活动影响，如果要向 AI agent 开放，必须“兼顾安全与客户体验”。

达美航空全球传播总经理 Heena Chavda 在回应我们关于该公司是否如一些用户抱怨的那样在封堵 agent 的提问时表示：“虽然达美航空目前没有建立任何合作或集成，让第三方 AI agent 能在我们的数字平台上代客户搜索或预订达美航班，但我们正在持续评估包括外部 AI agent 在内的新技术如何改善客户与达美航空互动的方式。”

美联航没有达美航空那么直接，但一位发言人向我们指出了其使用条款政策中的相关内容，其中写道，用户同意“未经美联航事先书面许可，不使用任何机器人、爬虫、其他自动设备或人工流程来监控或复制本网站或其包含的内容，或用于任何其他未经授权的目的”。（对于是否在封堵 Muse 等特定个人 AI agent 的追问，美联航未予回应。）

早期采用者在社交媒体上的抱怨提到了多个据称封堵 AI agent 的品牌，包括 Yelp、eBay、Zillow、Pizza Hut、Adidas 以及多家航空公司。一些人认为，封堵行为似乎最近有所增加。

还有几个人表示，eBay 暂停了他们的账户，原因是他们使用了 agentic AI。另有人抱怨，Google 在 Instinct 帮他们清理 Gmail 收件箱时将其踢出。

尽管人们力推让 agent 在餐厅订位以及完成其他繁琐任务，Yelp 却告诉我们，该平台不允许非人类流量，除非 agent 已付费通过其数据授权计划获取 Yelp 的内容和数据。这意味着，如果 agent 没有与 Yelp 建立正式合作，试图利用其网站获取报价、将用户加入等候名单或为其订位，很可能会失败。

eBay 向 TechCrunch 表示，其做法并非禁止所有第三方购物 agent 完成购买，而是通过政策限制未经授权的 agent 和行为，例如自动抓取和模型训练。

截至发稿时，Adidas、Zillow 和 Pizza Hut 要么未予回应，要么拒绝置评。

Cloudflare 是这一领域的重要参与者，它为网站提供保护，抵御可能利用其数据进行训练的 AI agent，并管理其他自动化活动。一些人怀疑正是Cloudflare 及其他类似的内容分发网络（CDN）目前正在干扰 Muse 的流量。这被归因于9 月 15 日对爬虫默认设置的更改，该更改允许网站所有者阻止 AI 训练，同时放行其他类型的机器人。此前出于安全原因被设置为阻止 AI 机器人的现有网站，随后被调整为在任何带有广告的页面上阻止 AI agent。

然而，当我们询问 Cloudflare 是否了解这些个人 AI agent（如 Muse 及其他）被阻止的情况时，该公司表示目前没有具体数据可以分享。它转而向我们推荐了其免费的公共数据平台 Cloudflare Radar。该网站显示了机器人活动的增加（Cloudflare 此前也曾对此发表过评论），但无法帮助区分好机器人和坏机器人。

Cloudflare 在减少网站 AI 流量方面也有既得利益，因为它现在运营着一个市场，AI 机器人必须为其访问的数据付费。它最近开始测试一款专为 AI agent 打造的新型网络浏览器。

鉴于这一领域发展迅速，Meta 决定为 Muse 访问建立特定的品牌合作关系似乎是正确的做法，其专注于新标准的决定也是如此。这样做可以向客户保证，至少其 agent 在这些合作伙伴的网站上是受欢迎的——因此任何访问问题都可以作为 bug 上报。

Meta 还在 Muse 应用内维护着一份“连接器”（即合作伙伴）列表，该列表持续增长。Meta 许多新宣布的合作伙伴尚未出现在这份列表中。但鉴于 Muse 的快速扩张，如今已包括面向小企业的合作工具，Muse 连接器列表很可能即将进行更大规模的重组。

Meta 在关于新宣布的标准制定计划的公告中表示：“拒绝一个个人 agent 就意味着拒绝其背后的客户。我们宁愿与企业合作解决根本问题，也不愿看到它们失去那个客户。存在一条对用户和企业都有利的路径。它始于明确的规范，赋予企业更可预测的控制权，并朝着 agent 更高效协作的方向演进。”
