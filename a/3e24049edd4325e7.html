GPT-6 的更好 prompt 缓存

评分 7/10：缓存命中率与成本延迟优化，与 agent 工程相关
原标题：Better prompt caching for GPT-6

要点

  • GPT-6 改进 prompt caching，默认提高缓存命中率，缓存输入 token 折扣最高 90%
  • 缓存折扣适用于 30 分钟内复用的共享前缀
  • 新增 Prompt Caching Dashboard 和诊断工具，可监控命中率、排查未命中原因

GPT‑6 让持久化 agent 能够连续数小时处理复杂任务，从重构代码库到产出经过充分调研的文档和演示文稿。这些 agent 背后的应用会发起一系列相互依赖的 API 请求，往往会沿用之前轮次中的相同指令、工具定义和上下文。OpenAI 会缓存这些共享上下文，以便在多个请求之间复用计算，从而缩短响应时间，并为开发者提供最高 90% 的缓存输入 token 折扣。

随着 GPT‑6 系列的推出，我们上线了改进后的 prompt 缓存系统，默认即可实现更高的缓存命中率。现在，对于在 30 分钟窗口内被复用的符合条件的共享前缀，我们会提供缓存折扣。我们还推出了新工具，帮助开发者监控缓存性能、诊断未命中情况，并选择要缓存 prompt 的多少内容。

新的 Prompt Caching Dashboard⁠（在新窗口中打开） 会显示你的应用输入中有多少来自缓存。你可以跟踪一段时间内的命中率，并使用输入构成图表来对比已缓存和未缓存的 token。这些视图有助于你发现缓存命中的下降，并评估应用变更对缓存性能的影响。

当你遇到意外的缓存未命中时，可以使用 prompt 缓存诊断工具⁠（在新窗口中打开） 来了解发生了什么。将某个请求与最近的响应进行对比，找出导致无法复用的模型、工具、设置或输入变化。受影响的估算 token 数量可帮助你评估影响规模，并决定如何优化集成以最大化缓存命中率。

{
  "prompt_cache_diagnostics": {
    "type": "cache_miss",
    "reason": "tools_changed",
    "comparison_reusable_tokens": 5629,
    "cache_missed_tokens": 5629
  }
}

选择要缓存的内容。显式缓存断点让你可以选择要复用哪些 prompt 前缀。更新后的 prompt 缓存指南⁠（在新窗口中打开） 说明了如何使用它们、缓存前缀在多长时间内仍符合条件，以及工具和输入的变化会如何影响复用。

调整推理力度而不破坏缓存。在 GPT‑6 模型上，你现在可以在多次响应之间 更改推理力度⁠（在新窗口中打开） 而不破坏缓存。对于更难的任务可以提高力度，对于常规的后续任务可以降低力度，只需追加一个 configuration_update，同时保持请求级别的推理力度不变。这样，你就可以在保留可复用上下文的同时，调整任务所需的推理量。

在工具和指令变化时保留缓存。随着 agent 的工具使用需求发生变化，请保持工具定义、schema 和顺序稳定，以便较早的上下文仍可复用。使用 allowed_tools 仅让相关工具可被调用，或在不需要工具时将 tool_choice 设为 none，而不是移除定义。使用新的 developer 消息在上下文末尾追加新指令，以覆盖较早的指令。请参阅我们的 工具变更管理指南⁠（在新窗口中打开）。

预热缓存以降低延迟。 预热⁠（在新窗口中打开）会提前准备好已知上下文，这样当请求到达时，模型可以更快开始响应。例如，应用可以在启动期间、用户提出第一个问题之前，预热共享指令、工具定义或参考资料。这样就把处理过程移出了用户的等待时间。
