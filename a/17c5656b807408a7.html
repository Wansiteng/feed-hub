CLI v3.0.65

Cline Releases · 评分 6/10：本地模型长会话截断的压缩重试机制，与本地推理相关

要点

  • CLI v3.0.65 修复本地模型长会话在输出 token 上限处中断的问题
  • 本地模型回复被截断时，CLI 会压缩对话并重试一次，仍失败则保留部分回答
  • hub 启动失败时给出具体原因，等待时间从 8 秒延长到 15 秒
  • 在本地模型上进行长时间会话时，回答不再因输出 token 上限而在中途中断。llama.cpp、Ollama 和 LM Studio 会将生成限制在剩余上下文和所设输出预算之内，因此纯文本回复可能被截断并导致运行失败。CLI 现在会压缩对话并重试该轮一次，若仍失败则回退到现有的简洁重试恢复机制；如果都无济于事，则保留部分回答。
  • 当 hub 启动失败时，错误信息现在会说明原因，而不再只是“No compatible hub runtime is available”。CLI 等待新启动 hub 的时间也从 8 秒延长到 15 秒，因为在 Windows 上安装或更新后的首次启动可能需要 8 到 13 秒。
  • 恢复会话时，会话中的错误信息现在会被保留。运行期间显示的错误（包括重试耗尽后报告的错误）过去在离开会话后就会消失；现在恢复会话时它会重新出现在记录中，但不会发送给模型，也不会计入压缩。
  • cline history update --title 和 --prompt 现在对 hub 管理的会话持久生效。此前新标题只在内存中更改，下次启动就会还原，而且更新元数据可能会丢失其他键，例如 pinned 状态。
  • 加载失败的插件不再在每次 prompt 时都消耗一次沙箱启动。CLI 会继续运行，只是不提供该插件的斜杠命令，并在 30 秒后重试加载，因此短暂的沙箱超时能够自行恢复。
  • 在空响应重试期间按 Esc 现在会立即取消，而不是等到退避延迟之后。
  • Yolo 模式（-y）会以更严格的输出规则提示模型：计划更简短，常规工具调用前不加开场白，代码和编辑直接写入工具调用，而不是先在文本中起草。预计叙述会更少，用于复述计划的 token 也会减少。
  • 新提供商：ai&，这是一个兼容 OpenAI 的端点，提供来自日本的开源权重模型。设置 AIAND_API_KEY；默认模型为 GLM 5.3。
  • 模型目录已更新：在同样的 209 家提供商下，模型数量从 6,237 个增加到 6,386 个。19 家提供商的默认模型发生变化。其中 11 家改为 Claude Opus 5.5（Cortecs、CrossModel、DigitalOcean、Eden AI、GitHub Copilot、两家 LLM Gateway 提供商、Ofox、Requesty、Vertex、Vivgrid），两家 StepFun 提供商改为 Step 5 Preview，Above 改为 MiMo V2.6 Flash，Fireworks 改为 Ember-1，Kenari 改为 DeepSeek V4.1 Flash，NanoGPT 改为 Aion 3.5，OpenCode Go 改为 Space Bunny Free，Pioneer 改为 GLiNER 2.5 Multi。如果你使用其中某家且未固定模型，默认模型将有所不同。
