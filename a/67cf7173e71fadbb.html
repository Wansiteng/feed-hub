评测：苹果超高价 M5 Ultra Mac Studio 让我变成 vibe coder

Ars Technica · 评分 9/10：Apple Silicon 本地 AI 实测，直接契合本地推理兴趣
原标题：Review: Apple's hyper-pricey M5 Ultra Mac Studio made me into a vibe coder

要点

  • 苹果 M5 Ultra Mac Studio 发布，最高配售价高昂，面向本地运行大模型的开发者
  • M5 Ultra 实为两颗 M5 Max 拼接，由四个独立芯片封装而成
  • M5 Ultra 最高 80 个 GPU 核心、1.2TB/s 内存带宽，支持 8 台外接显示器

今年春天，Apple 正式宣布：Mac Pro 已死。

当 Apple 还在使用 Intel 处理器和 AMD GPU 时，可扩展、可升级的塔式机箱是有意义的。但 Apple Silicon 芯片将 CPU、GPU 和内存接口整合在同一屋檐下，这使得那种可升级性不仅多余，而且根本不可能实现——除非牺牲芯片的一些关键优势。

而恰巧，Apple Silicon 将快速 CPU、强劲 GPU 和统一内存架构结合在一起，使其非常适合一种真正能压榨高端硬件的现代“专业”工作负载：在本地运行语言模型和 agent。

这正是 M5 Ultra Mac Studio 的核心受众所在。作为 Apple 的顶配机型，它在一次更新中跨越了两代处理器（如果你还记得的话，并没有 M4 Ultra）。最高端的 Studio 一直让大多数人觉得有些性能过剩，但如今，确实有一类深度拥抱 AI 的开发者或设计师，能从桌面上拥有这样一台系统中真正获益。

Apple 此前对来自运行 OpenClaw 等软件、在本地运行开放权重模型的人群的需求措手不及，再加上 AI 引发的内存短缺，这就是为什么这些系统中的大多数已经好几个月几乎买不到。新款 Mac Studio 正是在这样的背景下发布的。

新款 Mac Studio 的外观与 2022 年随 M1 Max 和 M1 Ultra 一同发布时相同。它是一个矮小的方盒，占地面积与旧款 Mac mini 一样为 7.7×7.7 英寸，但更高。Studio 的 Max 和 Ultra 两个版本外观一致，但 M5 Ultra 版本重了两磅，因为它的散热器中使用了更重但导热性更好的铜，以帮助为更强大的芯片散热。

两款 Studio 机型还配备了几乎完全相同的接口。背面有四个 120Gbps 的 Thunderbolt 5 接口、一个 10Gbps 以太网接口、一个 HDMI 2.1 接口和两个 5Gbps 的 USB-A 接口。正面，两款 Studio 都配有一个 UHS-II SD 卡读卡器，但 Max 配备两个 10Gbps USB-C 接口，而 Ultra 则配备两个额外的 120Gbps Thunderbolt 5 接口。

Ultra 的额外性能也体现在外接显示器支持上。M5 Max 最多支持五台外接显示器，而 M5 Ultra 最多支持八台，不过两者都会因所使用的分辨率和刷新率而有所限制。

M5 Max 如今已是众所周知的产品，Apple 自 3 月起便在 MacBook Pro 中出货该芯片。相比上一代 M4 Max，它通过为 CPU 引入新的“超级”核心，并将最大内存带宽从 546GB/s 提升至 614GB/s，实现了性能改进。GPU 核心数量保持不变（40 个），但每个 GPU 核心内置的新神经加速器有助于提升其在 MetalFX 超分和帧生成等 ML/AI 辅助技术方面的性能。

M5 Ultra 之所以是一次更大的跨越，原因有几点。首先，此前并没有 M4 Ultra，因此尽管产品只跳了一代，我们实际上跨越了两代处理器。

  • Apple M5 Ultra（低配）
    CPU S/P/E 核心：10S/20P · GPU 核心：64 · 内存选项：96GB/256GB · 内存带宽：1,228.8GB/s
  • Apple M5 Ultra（高配）
    CPU S/P/E 核心：12S/24P · GPU 核心：80 · 内存选项：96/256GB/512GB（计划中） · 内存带宽：1,228.8GB/s
  • Apple M3 Ultra（高配）
    CPU S/P/E 核心：24P/8E · GPU 核心：80 · 内存选项：128GB/256GB/512GB · 内存带宽：819.2GB/s
  • Apple M2 Ultra（高配）
    CPU S/P/E 核心：16P/8E · GPU 核心：76 · 内存选项：最高 192GB · 内存带宽：819.2GB/s
  • Apple M1 Ultra（高配）
    CPU S/P/E 核心：16P/4E · GPU 核心：32 · 内存选项：最高 128GB · 内存带宽：819.2GB/s

其次，芯片的构建方式实际上发生了相当大的变化。M1 Ultra、M2 Ultra 和 M3 Ultra 本质上都是将两颗 Max 芯片通过高速互连捆绑在一起，从而在无需承担制造单颗巨型芯片全部制造难题的情况下，获得大部分制造单颗巨型芯片的收益。

M5 Ultra 基本上仍是将两颗 M5 Max 芯片拼接在一起；这一点没有变化。该芯片包含最多 12 个超级 CPU 核心、最多 24 个 P 核心、最多 80 个 GPU 核心、32 个神经引擎核心、两个视频解码引擎和四个编码引擎，以及略高于 1.2TB/s（没错，是 TB，带 T）的内存带宽。这恰好是 M5 Max 所有主要规格的翻倍。

不同之处在于，这一代的 M5 Pro 和 M5 Max 本身就已经是通过硅互连连接在一起的两颗小芯片，这意味着 M5 Ultra 实际上是四块不同的硅片封装在一起。这种安排的潜在缺点是，裸片间互连的通信速度往往无法完全达到所有组件都位于同一块硅片上的水平。总体而言，Fusion 架构并未妨碍此前的 Ultra 芯片保持高速，也没有妨碍 M5 Ultra 保持高速。但 Ultra 芯片的性能从未随核心数量完美线性扩展，M5 Ultra 也是如此。

另外：新价格 :(

通常情况下，我们只需介绍新款 Mac 的硬件改进，并默认价格方面一切照旧——新硬件会自动比旧硬件更划算，因为售价相同。但今年由于 AI 引发的持续内存短缺，Apple 全面上调了价格。作为其最高端的电脑，配备最高端的内存和存储配置，Mac Studio 受到的冲击比其他 Mac 更大。

发布时，基础款 M4 Max Mac Studio 售价为 1,999 美元，配备的是略微精简版的芯片、36GB 内存和 512GB 存储。M5 Max Studio 起售价为 2,499 美元，上涨了 500 美元。搭载精简版芯片、96GB 内存和 1TB 存储的 M3 Ultra Mac Studio 起售价为 3,999 美元；相同配置的 M5 Ultra 则要价高达 5,499 美元，上涨了 1,500 美元。而这还只是基础型号。选择完全解锁的 M5 Max、64GB 内存和 1TB 存储——我认为这是尝试本地 AI 的性价比甜点——需要花费 3,799 美元，比 M4 Max Studio 发布时的价格贵了 900 美元。

至于 Ultra 呢？一款 256GB 内存/1TB 存储的型号，18 个月前售价为 5,599 美元，现在要价 9,499 美元——虽然算不上整整翻倍，但也差不多了，感觉上就是翻倍。M5 Ultra Studio 将会有 512GB 版本，但 Apple 尚未公布其价格。M3 Ultra 版本起售价为 9,499 美元，所以我可以很有把握地说，M5 Ultra 版本将会是一台 20,000 美元起步的电脑。要想对高端本地 AI 感兴趣，你首先得愿意为硬件支付比直接使用某家公司由 Nvidia 驱动的数据中心更高的前期费用。在这样的价格下，购买一组 Mac Studio 集群感觉就像自掏腰包建一个数据中心。

在讨论性能时，请记住这一点。

通用计算性能

几乎从所有指标来看，M5 Ultra 都是迄今为止最快的 Apple Silicon 处理器。它唯一落败的地方是单核 CPU 性能，Mac mini 上不起眼的 M6 以微弱优势胜出。但差距很小——比 M3 和 M4 两代之间的差距还小——这有助于让它不像上一代 Studio 搭载 M4 Max 和 M3 Ultra 发布时那样引人注目。

在我们的许多通用 CPU 和 GPU 测试中，Ultra 的 CPU 比 M5 Max 快 80% 到 90%，GPU 则快 50% 到 80%。这基本上与我们过去在 Ultra 芯片上观察到的情况一致——CPU 比 GPU 更接近 2 倍扩展。与即将退市的 M3 Ultra 相比，M5 Ultra 的单核 CPU 速度通常快约 30%，多核 CPU 速度快 50%，GPU 性能则根据测试不同快 33% 到 66%。正如你对两代升级的预期，这是一次大幅提升。

但我们也观察到了一些不太寻常的表现。Ultra 的 Geekbench 多核性能仅比 Max 快约 26%，而在我们基于 CPU 的 Handbrake 视频编码测试中，Max 完成 H.264 编码实际上更快（H.265 则仅稍慢）。

查看功耗数据或许能提供一种解释。根据 powermetrics 工具，在视频转码测试期间，M5 Max 和 M5 Ultra 的平均功耗都约为 75W。这也与 M3 Ultra Mac Studio 的功耗大致相当。但历史上，Max 版 Mac Studio 的功耗一直低于 Ultra 芯片。在我看来，这表明 M5 Ultra 受到了功耗限制，以使其保持在现有 Studio 设计的功耗/散热范围内。

但也可能只是一个 bug。在视频编码任务期间查看活动监视器，你不会看到每个 CPU 核心都被 100% 利用，而这是该测试的典型表现。powermetrics 报告称，在编码测试期间，Ultra 的所有 CPU 核心都以与 M5 Max 相同的持续时钟速度运行。如果存在与功耗或温度相关的降频，你会预期这些时钟速度更低。我已将发现报告给 Apple，如果收到回复会再作汇报。

为什么 AI 圈的人偏爱 Mac

我关于 vibe coding 的所有第一手认知几乎都是过去一周里学到的，所以如果我哪里说错了，还请见谅。包括 Apple 在内的许多 AI 模型提供商，也发布了一些能够绕过部分这些“硬道理”的模型。但总体而言，这应该算是一份准确的本地 AI 速成指南。

说到在本地运行 AI 模型，有两个硬件数字最为关键。第一个是你拥有的 GPU 内存容量。第二个是你的内存带宽，也就是 GPU 与系统其余部分通信的速度。

显存决定了你能运行的模型规模——模型几乎需要完整加载进 GPU 内存，因为超出部分要么会溢出到主系统内存（慢），要么在最坏情况下落到磁盘上（更慢）。

除此之外，尤其是在编程场景下，你还需要额外的内存来存放“上下文”，也就是单个 agent 在内存耗尽前能记住的信息量。对于基础的问答式聊天机器人交互，你不需要太多上下文。但要编写一个完整的应用，你就需要留出大量 RAM 作为上下文，这样 agent 才不会在复杂任务进行到一半时“忘记”自己在做什么。

存在一些交接机制——一个 agent 可以把一次会话压缩成一个包含大部分相关信息的文件，再传给另一个 agent，从而有效地重置上下文。但这种机制难免会有信息遗漏，尤其是在一开始就没有多少上下文可供压缩的情况下。

内存带宽并不是决定模型输出新词（“token”）速度的唯一因素，但它可能是最重要的单一因素。与内存容量以及计算机进出内存的数据搬运速度相比，就连内存所挂载的 GPU 的速度和能力都没那么重要。

Apple Silicon Mac 之所以在运行这类模型上流行起来，是因为它们恰好踩中了甜点区。它们提供的内存带宽不如专用桌面 GPU（一块 5 年前的 Nvidia GeForce RTX 3060 12GB 提供 360GB/s 带宽，比 M5 Pro 高出近 20%；一块 RTX 5070 12GB 提供 672GB/s，超过 M5 Max）。但一台 64GB 的 Apple Silicon Mac 提供的 GPU 内存比你能买到的任何单块消费级 GPU 都多，其内存带宽也足够快，而且能效远高于一块 RTX 5090 或两块 RTX 3090。而 96GB、128GB、256GB 和 512GB 的 Apple Silicon Mac 更是为运行更大规模的前沿级模型打开了大门。

显然，这些顶配机型目前并不便宜，但这或许能解释为什么连 Mac mini 这种产品都突然变得一机难求。部分也因为硬件非常适合这类工作负载，Apple 的 MLX 框架已经得到了相当不错的优化，并获得了不同语言模型以及 LM Studio Bionic 等本地 AI 应用的广泛支持。

除了这些指标，还有一个叫“首 token 时间”（TTFT）的东西——也就是你向模型提交 prompt 到模型处理并开始响应之间经过的时间。这正是 M5 世代相较 M4 及更早机型的改进之处：Apple 在 GPU 中加入的神经加速器大幅加快了 TTFT，让任何本地运行的模型都感觉更跟手。

再加上 M5 Ultra 相比 M3 Ultra 大幅提升了内存带宽，你就能明白为什么这款 Mac Studio 特别适合这类工作。它比去年的 M3 Ultra 整整跨了两代，这让它看起来甚至比 M5 Max Studio 或 M5 Pro Mac mini 更值得选。

我成了 vibe coder

在标准的一系列 benchmark 之外，我一直在 Studio 上尝试一些本地 vibe coding，这也是我第一次这么做。在几位比我走得更远的人推荐下，我下载了 LM Studio Bionic 和 Qwen 3.8 27B 模型。

说到编程和开发，我那点基本的 HTML 和 CSS 知识勉强够改改现成的模板，但我想学更多的心愿一直远超我的能力。怪 ADHD 也好，怪没空闲时间也好，怪什么都行——反正我脑子里的某个东西，在我唯一一次尝试上的编程课上，刚学完“Hello world!”没几节课就开始抗拒了。

我就是怎么都学不进去。

用这台 M5 Ultra Mac Studio 和 LM Studio Bionic 跑一个完全本地的、具备编程能力的语言模型，是我很久以来在新科技产品上玩得最开心的一次。而且说这话的我，平时可是个普遍讨厌生成式 AI 的人。

但vibe coding在过去一两年里流行起来是有原因的。如果你足够了解情况，能告诉系统你想要什么，你就能做出一些真正有用的、确实能运行的东西。

我参与一个读书播客已经将近十五年了，我负责我们的账务——这算是副业中的副业。多年来，这项工作一直涉及把银行对账单上的数字手工录入到我搭建的一个电子表格里，用来追踪我们的收入、支出和预估税负。这活儿太轻了，不值得永远为QuickBooks付费——那软件做了太多我们不需要的事。这属于那种大概可以解决、想起来就烦人，但你遇到它的频率恰好低到永远懒得去修的问题。

现在它修好了！

首先，我让Qwen模型写了一个Python脚本，把银行对账单PDF转换成电子表格，并按我想要的方式格式化和排序。然后我在它周围搭了一个Web应用，这样以后我就能轻松上传新的对账单，而不用去折腾LLM或Python脚本。

我对此相当矛盾，但用几个下午的时间做出一小段软件来解决某个棘手的、只属于你自己的问题，这种吸引力是无可否认的。而且在这个例子里，你可以在自己家里的硬件上完成，数据从不离开你的家，耗电还比一块PC显卡少。

我大概花几美元的token就能在一个下午解决这个问题，但把多年的财务数据发给Anthropic或别的谁，是我无法接受的。用这种方式，我就不必这么做。

Qwen 3.8 27B模型是“开放权重”的，并以Apache 2.0许可证发布，所以使用上没有限制。它还提供不同的“量化”（基本上就是用一点精度换取更小的体积），帮助它适配不同内存容量的Mac。我想说，32GB是你用来运行相当能干的4K量化、并拥有足够上下文来处理非常小的项目或对现有项目做窄范围修复的最小内存量，但64GB是更好的目标，这样系统既有大上下文窗口，又有足够内存让你同时把Mac当普通电脑用。

在macOS 27.0上运行的LM Studio Bionic中使用4K量化的默认设置，我的日常主力机M2 Mac Studio在一个关于启动新网站项目的示例提示上，达到了大约每秒18到20个token的速率。一台Framework Desktop（基于Strix Point Ryzen AI Max+平台，因其大容量且速度尚可的统一内存而在本地AI爱好者中相当受欢迎）在Ubuntu 26.06和AMD的ROCm后端上，对同一提示也达到了大致相同的每秒18到20个token。

这个每秒token数绝不算糟糕，意味着系统生成文本的速度差不多和我阅读的速度一样。但对于更长的编程项目（尤其是如果你开着“推理”，让机器人先吐出一大串词序列才定下行动方案），这意味着要等很久，而且随着你深入长上下文窗口，每秒token数确实会开始进一步下降。

M5 Max Mac Studio在同一提示上的每秒token数约为31。M5 Ultra则略高于50。（顺便说一句，这就是为什么搭载M5 Pro的Mac mini做这类工作不太行，即使有64GB内存——它的内存带宽只有M5 Max的一半，而内存带宽通常是这类工作负载最敏感的规格。）

只要你的期望不太高，并且愿意有条不紊地排查和调试，这两款 Mac Studio 芯片都确实能胜任这类工作。agent 第一次几乎总会在某些地方出错，而我在 vibe coding 过程中投入的大量时间和精力，都花在了逐个修复、把功能打磨成型上。
