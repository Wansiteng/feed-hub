一个用于深思熟虑的软件设计的开源画布

Whiteboard 是一款开源桌面应用，人类和 agent 可以在同一个工作空间中共同设计软件架构。

Whiteboard 可以接入你已经在使用的工具——例如 Claude Code、Codex 等——并为你的 agent 提供一个 SDK，让它在应用内画布上绘制内容来描述自己的工作。

这里有一段 1 分钟的演示视频，做了更详细的说明：https://www.youtube.com/watch?v=ChPn3ftULWE

  1. 下载 Whiteboard 并打开应用。
  2. 在欢迎界面连接 Claude Code、Codex 或其他编程 agent。
  3. 让你的 agent 将当前分支与最新的 main 分支进行对比， 并在 Whiteboard 中打开结果。

根据我们的经验，Whiteboard 与 GPT-6 Sol、Claude Opus 5.5 这类模型配合效果最佳，它们在智能、成本和速度之间取得了良好平衡。

以下是一些如何高效使用 Whiteboard 的示例 prompt。我们正在努力确保正确的选择默认内置到系统 prompt 中——这也是这个系统开源的原因之一！——但在此之前：

嘿，这堆 commit 的设置是为了让我能有一个 [api] 来实现 [目标]

我想看到：

  • 建议的 api
  • 示例
  • 这样做的动机（如果你能在上下文/仓库中找到的话）

然后我们可以深入实现，并解释各部分是如何运作的。

针对一次添加遥测的改动：

你能给我解释一下最新那个 posthog pr 里的遥测改动吗 https://github.com/devdotfast/whiteboard/commit/4837e107946e27ebad50c282eb0f2585210d2a35 —— 我们在追踪什么，如何据此构建好的仪表盘或产品漏斗？对于卡顿、错误、崩溃等情况我们是怎么处理的……用 whiteboard

如果你看到任何不满意的地方，把它在剪贴板中高亮出来交给你的 agent，它就能在 Whiteboard 上重新绘制以满足你的需求！

从图表到代码

纯 HTML 工具无法提供便捷的方式来将规格说明或图表与代码关联起来；这尤其棘手，因为权衡取舍往往只有在第一轮实现之后才会被发现。在 Whiteboard 中，当你点击时序图、实体关系图，或 agent 追踪记录中的引用等可视化内容时，你可以直接跳转到底层代码。在浏览代码时，你可以开箱即用地获得 VSCode 的快捷键和 LSP 支持。

原始 diff 视图可能非常嘈杂，所以我们用 Rust 写了一个语义化、感知 AST 的 diff 查看器，让你只查看与自己相关的代码改动。我们设置了一些合理的默认值：新增的大型函数会被总结为伪代码，单元测试和文档改动等内容会被折叠/隐藏。这一切都可以通过基于 WASM 的插件系统进行自定义。

我们发现很难推断我们的 agent 自主做出了哪些决策，以及这些决策如何影响一次改动。因此我们为 agent 构建了工具，让它们能在 Whiteboard 上查询并关联自己的追踪记录，这样你就能可视化自己设定的需求，理解它们是如何被实现的，并了解 agent 自主做出了哪些决策。

开源，运行在你自己的机器上

Whiteboard 采用 MIT 许可证，并针对你本地的代码检出运行。面向团队的托管产品已在规划中，而且一切将始终可以自托管。

  • 你目前无法在 Whiteboard 中编辑文件。如果你发现自己想要这样做，请提交一个 issue！

  • 在一次审查中跨多个仓库工作和浏览文件的支持还不够完善。

  • 虽然你可以通过分享按钮在多台机器之间共享审查，但审查共享后所做的更新不会对其他人显示。你需要重新分享该审查。

欢迎贡献和反馈。

阅读 CONTRIBUTING.md 了解设置和 pull request 工作流程，并遵守 Code of Conduct。按照 SECURITY.md 中所述报告漏洞。有问题？在 Discord 上提问。

Whiteboard 针对本地检出运行。匿名遥测不包含你的代码、diff、Whiteboard 文本、prompt 或模型输出。阅读 隐私概览，查看完整的 遥测参考，或随时关闭遥测。

Whiteboard 在 MIT License 下提供。内置的 Code - OSS fork 保留 Microsoft 的 MIT 许可证和第三方声明；参见 apps/review-desktop/LICENSE 和 apps/review-desktop/UPSTREAM。

既然大家都在使用专用的 agent TUI 和桌面应用，我们现在只用文本编辑器来逐行审查 diff，所以我们想为什么不做一个专门用于审查代码的文本编辑器呢。既然如此，不如以市面上最成功的开源编辑器作为起点。

我们内置 Code OSS，而不像其他 fork 那样维护补丁，因为 coding agent 很难处理补丁，而且原版 VS Code 中有很多我们不需要的东西（比如，如今约 45% 的代码库都是 Copilot 😬）。

我们定期监控上游 Code OSS，并在安全/功能补丁发布时合并进来。
