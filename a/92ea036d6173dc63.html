推出 GPT-6 Sol 和 Luna

评分 9/10：重要新模型发布，能力与成本分层，必读
原标题：Introducing GPT-6 Sol and Luna

要点

  • OpenAI 发布 GPT-6 Sol 和 GPT-6 Luna，主打成本效率
  • Sol 和 Luna 的 API 价格比 GPT-5.6 促销价降低 50%
  • GPT-6 Sol 在 AutomationBench 上以 Opus 5 的 9% 成本超越其最高表现

本月早些时候，我们推出了 GPT‑6 Astra，这是全球最智能、最对齐的模型。尽管最严苛、最重要的项目仍然需要 Astra 的完整深度，但实际工作会以不同的规模、节奏和预算展开。

因此，我们通过 GPT‑6 Sol 和 GPT‑6 Luna 扩展了 GPT‑6 家族。GPT‑6 Astra 开启了新一代智能——这些模型通过推进成本效率的前沿，帮助将这种智能的收益更广泛地分发出去。我们使用与 GPT‑6 Astra 类似的方法训练了 GPT‑6 Sol 和 Luna，将 Astra 在专业工作、事实性、编程、计算机使用和对齐方面达到最先进性能背后的进步，带到了更快、更实惠的模型中。

GPT‑6 系列模型在成本—智能曲线上全面领先，在每个层级都具备卓越能力，并配有能够高效大规模交付这些能力的基础设施。缓存和推理方面的改进让我们能以更低的成本提供这些模型，我们通过将 Sol 和 Luna 的 API 价格较其 GPT‑5.6 促销价降低 50%，把这些节省直接传递给用户和客户。这些改进共同让先进 AI 在更多日常任务和大规模应用中变得切实可用。

价格按每 100 万 token 计算。

GPT‑6 Astra 依然是我们在各方面表现最好的模型。当你想要最佳结果和不妥协的体验时，请选择它。

GPT‑6 Sol 和 Luna 为你已经熟悉并使用的模型带来了智能升级和成本效率，覆盖了完成复杂工作最有用的各项能力。

GPT‑6 Sol 能够承担困难的工作任务，同时凭借更高的使用限额和更低的成本，给你更多迭代空间，相比同价位的竞品模型提供更强的智能和更好的结果。

在跨应用测试业务流程的 AutomationBench 上，以 xhigh 推理强度运行的 GPT‑6 Sol 表现优于以 max 强度运行的 Claude Opus 5，而每任务成本仅为 Opus 5 的 9%。在 high 强度下，GPT‑6 Luna 相比其前代提升了 5.4 个百分点，每任务成本降低 58%。

GPT‑6 Sol 也以远低于 Claude Fable 5.1 的成本超越了后者，甚至胜过低推理强度的 GPT‑6 Astra。

在评估 agent 处理复杂专业工作流的 Agents’ Last Exam 上，以 max 强度运行的 GPT‑6 Sol 得分为 56.4%，高于 Claude Opus 5 在该评估中的最高分，而每任务成本低 60%。

答案是否有用取决于事实是否正确，我们正在事实可靠性方面持续取得进展。在我们的内部事实性评估中——该评估基于用户标记出我们模型错误的去标识化真实对话——GPT‑6 Sol 的错误数量约为其前代的一半，以低得多的成本接近 Astra 级别的可靠性。GPT‑6 Luna 也有大幅提升；在更高推理强度下，它以约百分之一的成本达到 GPT‑5.6 Sol 的水平。

今年，coding agent 开始处理比以往任何时候都更复杂、范围更广、持续时间更长的任务。在 OpenAI，我们的内部使用量呈指数级增长。按 API 价格计算，中位数研究人员的每日 token 使用量已超过 600 美元，而第 90 百分位的研究人员则超过 7,000 美元（研究加速：OpenAI 内部视角⁠）。随着 coding agent 承担更长、要求更高的任务，持续使用的成本变得更加重要。GPT‑6 Sol 和 Luna 将强大的编码性能与更低的 API 价格相结合，让开发者有更多空间进行迭代，也让团队有信心对 Codex 提出更宏大的要求。

在FrontierCode上，该基准评估 coding agent 生成的改动是否可直接合并到真实代码库中，GPT‑6 Sol 相比 GPT‑5.6 Sol 有大幅提升，并且能够以低得多的成本达到 Claude Fable 5.1 xhigh 的水平。

在 DeepSWE v1.1 上，该基准测试在真实代码库中处理复杂软件工程任务的性能，GPT‑6 Sol 在 max effort 下得分 68.8%，与 Claude Fable 5 在该评估中的最高分——xhigh effort 下的 69.9%——仅差 1.1 个百分点，而每任务成本约低 80%。

GPT‑6 Luna 在 max effort 下得分 66.6%，与 medium effort 下的 Claude Opus 5 和 Fable 5 相当。在这些对比中，Luna 的每任务成本比 Opus 5 低 93%，比 Fable 5 低 96%。

尽管 GPT‑6 Astra 仍是全球最强的 computer use 模型，但 GPT‑6 Sol 和 Luna 提供了比前代更具成本效益的性能。在OSWorld 2.0 offline上，GPT‑6 Sol 在 xhigh effort 下取得了与 medium effort 下 Claude Opus 5 相近的分数——60.5% 对 60.3%——而每任务成本约低 80%。GPT‑6 Luna（max）能够以 GPT‑5.6 Sol（medium）十分之一的成本超越后者。

我们还将 GPT‑6 Astra 改进后的沟通风格带到了 Sol 和 Luna 上，我们认为这在技术和编码对话中会尤为明显。可以期待更清晰、更少术语、更少奇怪的措辞、更少低价值细节，以及整体上略微更简短但不失实质的回答。

除了更低的 token 价格，我们还在帮助基于 GPT‑6 构建的开发者节省应用程序复用上下文方面的开支。我们改进了 GPT‑6 的 prompt caching，默认提供更高的缓存命中率，帮助 agent 复用更多上下文、更快响应，并享受缓存输入 token 读取 90% 的折扣。

开发者还有更多方式来衡量和优化其缓存性能：

  • 监控与诊断。 Prompt Caching Dashboard⁠（在新窗口中打开）显示有多少输入被缓存以及随时间的变化。 诊断工具⁠（在新窗口中打开）有助于解释错失的缓存机会以及需要修复的地方。

  • 在不破坏缓存的前提下调整推理强度与工具可用性。 面对更难的任务时提高推理强度⁠（在新窗口中打开），面对更简单的后续问题时则降低强度，并可根据 agent 需求的变化启用或禁用工具⁠（在新窗口中打开）。现在这两项控制都会保留此前的上下文以供缓存复用。

  • 优化哪些前缀会被缓存。 显式断点让开发者可以自行决定缓存 prompt 前缀的结束位置。这使开发者对缓存复用拥有更多控制权，并可提升性能。

GitHub 表示，过去几个月里，这些改进使 OpenAI 模型数十亿次请求中需要重新处理的 prompt token 占比降低了 50% 以上，帮助 Copilot 更快响应。

GPT‑6 Sol 和 Luna 建立在我们迄今对齐程度最高的模型 Astra 所引入的对齐工作之上。在对齐评估中，Sol 和 Luna 均较其对应的 GPT‑5.6 有所改进，包括降低了就其编码工作做出误导性陈述的比例。

以下评估刻意测试了具有挑战性的场景，并不衡量典型使用中的失败率。完整结果请参阅系统卡⁠（在新窗口中打开）。

GPT‑6 Sol 和 GPT‑6 Luna 即日起在 ChatGPT Work 和 Codex 中面向所有 Plus、Pro、Business、Enterprise 和 Edu 用户开放。Free 和 Go 用户可在桌面应用中访问 GPT‑6 Luna。这些模型尚未在 Chat 中提供。在 OpenAI API 中，它们分别以 gpt-6-sol 和 gpt-6-luna 提供。

为保持对所有人的服务稳定，我们计划在当天内逐步在 ChatGPT 中推出这些模型。如果你在 ChatGPT Work 或 Codex 中看不到新模型，请稍后再试。

GPT 的评估在我们的研究环境中或通过我们的 API 进行，由于系统 prompt、可用工具等差异，其输出可能与生产环境中的 ChatGPT 略有不同。竞品模型的评估取自公开报告。在无法获得 Claude Fable 5.1 的分数时，报告的是 Claude Fable 5 的分数。
