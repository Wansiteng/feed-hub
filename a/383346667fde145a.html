2026 年 LLM 进展（截至目前）

评分 8/10：Simon Willison 年度 LLM 趋势长文，信息密度高
原标题：2026 in LLMs (so far)

要点

  • Claude Opus 4.5 和 GPT-5.1 让编码 agent 从常出错变得日常可用
  • Simon Willison 用「骑自行车的鹈鹕」SVG 测试评估新模型
  • 年主题是「更有野心」，用编码 agent 同时推进多个新项目

周五，我在圣何塞的WeAreDevelopers 北美世界大会上做了闭幕主题演讲。我把过去一年的关键趋势串联起来，按时间顺序梳理了 2026 年发生的一切。视频在 YouTube 上；以下是我为配合演讲准备的带注释幻灯片和笔记。

#

我将快速带大家浏览一遍 2026 年迄今为止发生的所有事情。这一年还没结束呢！

#

对我来说，2026 年早在两个月前的 2025 年 11 月就开始了。

#

11 月发布了两个重要模型：Claude Opus 4.5 和 GPT-5.1。

和通常的新模型一样，它们只是对前代模型的渐进式改进。

但每隔一段时间，当模型改进时，它会越过一条看不见的线，某些原本不太行的事情开始变得可行了。

这次开始变得可行的是它们的编程 agent。Claude Code 自 2025 年 2 月就已存在，Codex 稍晚一些。

这两个新模型，与各自配套的编程 agent harness 结合后，从“经常出错”提升到了“可靠到足以日常使用”。

#

几年来，我一直通过让新模型“生成一只骑自行车的鹈鹕的 SVG”来评估它们。这大概是世界上最蠢的 benchmark——从中能学到的东西非常有限。

但这对模型来说仍然是个挑战，因为画鹈鹕很难，画自行车很难，而且鹈鹕根本就不会骑自行车。

这是 11 月的最先进水平。Claude 还是画不好自行车！GPT-5.1 的自行车车架也相当糟糕。

#

同样在 11 月，一个名为“Warelay”的冷门 GitHub 仓库有了第一次提交。我们稍后会回到这个仓库。

#

然后是 12 月的假期，一些独立开发者休息了一段时间，许多人开始摆弄这些新的编程 agent 模型组合……我们开始意识到，它们能做到的事情比以往多得多。

到了 1 月，我们许多人都很兴奋，开始把这些东西付诸实践。

#

每年我都会给自己定一个新年决心，而且从我记事起就一直是同一件事：保持专注。少接新项目。努力把已有项目做完。

#

今年我决定，既然以前从未奏效，那我就反其道而行之。

我们现在有编程 agent 了，看看它们能做什么。我要想接多少新项目就接多少！

（你可以在年底问我这个决定到底好不好。我现在手里同时转着很多盘子。）

“更有野心”成了这一年的某种主题，因为要找到这项技术的极限，唯一的办法就是不断推进，直到它们行不通为止。

#

我还和 Bryan Cantrill、Adam Leventhal 一起上了Oxide and friends 播客，分享了对未来一年（以及三年和六年）的预测。

事后看来，我对 LLM 的预测相当保守。

我说过“LLM 能写出好代码将变得无可否认”——我认为我们现在已经做到了。

我预测我们最终会解决沙箱问题。我数了一下，这次会议的 277 场演讲中约有 40 场以某种方式涉及沙箱或 agent 安全，所以至少我们在这方面投入了大量精力！

我曾预测 coding agent 安全领域会遭遇"一场挑战者号式的灾难"。今年围绕 agent 安全的噪音确实不少，不过我预测的那种具体灾难（coding agent 被劫持并造成现实世界的经济损失）并没有真正发生。

我们还加了一条玩笑式的预测，说教皇会对 LLM 的经济影响发表看法。

#

我还预测，新西兰的鸮鹦鹉今年会迎来一个出色的繁殖季。

这是一种生活在新西兰的鸟。它们是不会飞的夜行性鹦鹉。我觉得它们看起来有点矮胖，但我觉得它们很美，年初时全世界只有 236 只这种鹦鹉。

鸮鹦鹉只有在陆均松大量结果的年份才会繁殖，而这种情况已经四年没有出现了……但今年陆均松的果实看起来非常好。

照片由 Kimberley Collins 拍摄。

#

同样在那期播客里，我们为"那种 AI 引发的倦怠感——软件工程师因为 AI 什么都能做而变得无精打采"创造了一个词（功劳全归 Adam）。

我们把它叫做 Deep Blue。

这是贯穿全年的一个主要主题，本次大会上有好几位演讲者都提到了它。

作为一名软件工程师，我的职业生涯中从未有过哪一年像这样，一切都变化得如此之快、如此之剧烈。

今年我做的很多事情，就是试图接受这一点，以及这对我的职业意味着什么。

#

同样在一月，我患上了我称之为AI 狂热的症状。

这和 AI 精神病不是一回事。

患上 AI 狂热时，只要你的 agent 没有在为你构建什么东西，你就会觉得那是在浪费时间。你会失眠，因为你可以熬得更晚，让 agent 去干活。

我的 AI 狂热表现为一些荒唐地过于宏大的项目。

我用 Python 完整构建了一个 JavaScript 解释器，是从 Fabrice Bellard 的 MicroQuickJS 凭感觉移植过来的。

然后我又用 Python 构建了一个 WebAssembly 运行时。

这些项目相当有用，因为它们某种程度上治好了我的 AI 狂热……因为在我构建完这些东西之后，我看着它们，问自己："这个世界需要一个缓慢、满是 bug、半生不熟的 Python JavaScript 解释器吗？"

我觉得这个世界不需要。

#

我确实从中得到了这个：https://simonw.github.io/micro-javascript/playground.html

#

这个页面运行的是我用 Python 构建的 JavaScript 解释器，它在 Python 中运行，用的是 Pyodide——也就是编译成 WebAssembly 的 Python，运行在 JavaScript 中，运行在浏览器里。

这是一套美丽的恐怖堆栈。今年我在 WebAssembly 上玩得非常开心。

#

到一月底，我们看到的那个十一月启动的仓库已经改过好几次名，先是 CLAWDIS，然后是 CLAWDBOT，接着是 Moltbot，最后定为 OpenClaw。

#

此时 OpenClaw 已有 8,300 次提交，而项目启动还不到两个月。我今天看了一下，现在已经超过 100,000 次提交了！

这是现存最"凭感觉编码"的软件。

（这是我如何生成那份改名列表的。）

#

这开启了 OpenClaw 革命。它实际上定义了一个新的软件类别。

有一个我很喜欢的通用术语。我们把这类软件称为“Claw”。有 OpenClaw、NanoClaw、IronClaw、PicoClaw……

如今它们被重新包装为“个人 agent”或“通用 agent”，但我仍然喜欢把它们称为 Claw。

#

湾区的 Apple Store 里 Mac Mini 售罄，因为太多人买 Mac Mini 来运行 OpenClaw！

Drew Breunig 说，这是因为你的 OpenClaw 是一只电子宠物，你买一台 Mac mini 当作水族箱来养你的 claw，这还挺可爱的。

#

同样在一月，我们有了这个网站。

这就是 MoltBook，一个面向 AI agent 的社交网络，其理念是让你把你的 Claw 送去和其他所有 Claw 交谈，因为这样做还能出什么岔子呢？

该网站于周四上线。它在周五爆火。它在周一被《纽约时报》报道。而到了周二，所有人都忘了它的存在，因为它淹没在垃圾内容和 spam 的洪流中。

Facebook/Meta 一个月后收购了它。

#

二月，一家名为 StrongDM 的公司描述了他们所谓的软件工厂。

#

他们在《软件工厂与 agent 时刻》中写到了这一点。我当时发布了自己的笔记，因为我早在十月就亲眼看过他们的演示。

Dan Shapiro 将这种方法称为黑暗工厂，其理念是，如果你的工厂自动化程度足够高，你就可以关灯，因为你甚至不需要看到正在发生什么。

StrongDM 提出了他们自去年七月以来一直遵循的两条软件开发规则。

#

第一条是代码不得由人类编写。

你编写的任何代码都必须经过编码 agent 处理。

这在二月听起来很激进，但我想这个房间里有很多人今天基本上就是这样生活的。

#

第二条规则是代码不得由人类审查。

你不被允许阅读代码！

这在今年大部分时间里一直是一个巨大的话题。这次活动的许多会议都关于代码审查以及你如何能绕过这一点。

我觉得 StrongDM 有趣的地方在于，他们比我们其他人领先了六个月，他们一直在探索构建软件意味着什么——不阅读代码，但仍然确信软件质量很高。你能用这些 agent 做什么来帮助验证它们的工作？

StrongDM 是一家安全公司，他们在这个项目上拥有数十年经验的人。他们很大程度上是在探索用这些东西可能且负责任地做到什么的边界。

#

同样在二月：四年来第一只 kākāpō 雏鸟在情人节孵化。繁殖季开局良好！

#

同样在二月……Google 发布了 Gemini 3.1 Pro。那只骑自行车的鹈鹕画得相当不错！链条位置正确，两只脚都踩在踏板上。车筐里还有一条小鱼。

#

随后，Google 的 Jeff Dean 发了一段推文视频，对比 Gemini 3 Pro 和 Gemini 3.1 Pro，视频里有一只骑自行车的动画鹈鹕、一只骑大小轮自行车的青蛙、一只开小汽车的长颈鹿、一只穿旱冰鞋的鸵鸟、一只玩滑板翻板动作的乌龟，还有一只开加长豪华轿车的腊肠犬。

这让人很沮丧，因为我那个“鹈鹕骑自行车”测试的防护逻辑一直是：“要是它们能画出一只完美的骑自行车鹈鹕，我就换别的动物、别的交通工具。”

Google 把所有动物配所有交通工具都训练了个遍！到这一步，他们已经把我的 benchmark 给攻破了。

#

二月开始的另一件事是 Tokenmaxxing。当时有报道说 Meta 把 AI 采用率正式纳入绩效考核，微软希望每位员工都用 AI，Uber 则夸口说 90% 的工程师都在使用 AI 工作流。

#

可几个月后，Meta 开始严控 token 用量，微软表示 token maxxing“不是我们优化的目标”，Uber 也对员工的 AI 支出设了上限。

于是 Tokenmaxxing 直线冲高，又直线回落——因为事实证明，agent 实在太贵了。

去年，想在 AI token 上花超过 50 美元都难，因为我们根本没什么有意思的事可做。后来 agent 爆发了，现在你真能一天花掉 1000 美元来做正经工作。

这也是 Anthropic 估值一路飙升到可能上万亿美元的原因。

AI 似乎在 2026 年实现了产品市场契合，主要靠 coding agent 推动。

到了三月，我们迎来了 OpenClaw 的巅峰。

#

这些照片来自中国，当地公司举办了 OpenClaw 安装派对，非技术爱好者也排起长队，等着别人帮自己在个人设备上装好 Claw。

我认为这证明了这类 Claw，也就是个人 AI agent，存在真实的市场需求。事实证明，普通人确实想要一个古怪的小 AI agent，能替他们做点有用的事。

Claw 本质上就是一个戴着不那么吓人帽子的 coding agent。底层工作原理几乎一样——在你的电脑上编写并执行代码来完成任务。

竞赛随之展开：谁先造出安全的 Claw——一个能交给普通人、而他们不会立刻搬起石头砸自己脚的 Claw。

Meta 的 Muse 三周前发布，目前位居 iPhone App Store 免费榜榜首。它似乎正在消费者中迅速走红。

我还不确定用 Muse 是不是真的不会砸到自己的脚，但我想很快就能见分晓。

#

四月，我们迎来了一次模型发布，但模型实际上并没有发布。

#

Anthropic 宣布了新的 Claude Mythos 模型，随后表示它太危险，只能在受信任的安全研究人员范围内发布。

Mythos 在入侵方面真的、真的非常擅长。

“太危险了”这种营销手段，AI 公司从 GPT-2 时代就开始用了。每当一家 AI 公司说我们造出了“太危险”的东西，人们自然会有点怀疑。

我认为 Mythos 的说法是可信的，因为我亲眼看到编程 agent 在发现普通 bug 方面变得多么厉害。我在 Anthropic 的 Project Glasswing——将 Claude Mythos 限制给安全研究人员——在我看来是必要的 一文中写过这一点。

事后看来……没错，这些模型在发现漏洞方面确实变得非常强了！

#

2026 年的另一个关键趋势是开放权重模型的能力大幅提升，包括那些可以在笔记本电脑上运行的模型。

4 月 16 日，我在笔记本电脑上运行了新的 Qwen3.6-35B-A3B，它给我画的骑自行车的鹈鹕比 Anthropic 全新的 Claude Opus 4.7 画的还要好！

Opus 4.7 画的自行车很糟糕。我笔记本电脑上的 Qwen 画出的自行车形状正确，鹈鹕也相当不错！

那是一个 21GB 的文件在我笔记本电脑上运行的结果。

#

Qwen 画的鹈鹕太好了，我怀疑它们可能作弊了，所以我让它再画一只骑独轮车的火烈鸟。结果它再次轻松击败了 Claude Opus 4.7。

今年发布的本地模型简直是非凡的。

到了 5 月……教皇也掺和进来了。

#

在一月份的播客节目中，我们曾预测教皇会对 AI 发表一些看法。

5 月，教皇利奥十四世发布了一道通谕，主题是“在人工智能时代守护人的尊严”。

以下是我对该文件的笔记。

#

事后看来，这根本不应该让人意外。

我们现任教皇的名号是利奥十四世，因为他在选择名号时，以利奥十三世为榜样——利奥十三世是 1891 年撰写关于工业革命通谕的教皇。

《新事》通谕是一份极具影响力的天主教神学文献，间接促成了我们如今五天工作制的出现。

当我们的新教皇就任时，他选择以教皇利奥十三世的名号命名，因为他预计自己需要以类似的方式撰写关于 AI 革命的文章。

我们播客中的玩笑预测毫无价值，因为这件事注定会发生。

#

Anthropic 的联合创始人之一 Christopher Olah 出席了教皇宣布新通谕的活动。

Corey Quinn 指出：

让真正的教皇把你产品特定的技术局限性奉为精神论著，这是我见过的最伟大的供应商游说行为。

#

与此同时，在 5 月，RubyGems 宣布他们遭到了攻击。不明身份者向 RubyGems 服务器上传了数千个可疑软件包，以至于他们不得不关闭用户注册。

我们先把这件事放一放，留待以后解开谜团。

#

到了 6 月……Claude Fable 5 发布了！

我们得到了一个被阉割过的 Mythos 版本，这样它就不会帮助我们入侵系统或制造生物武器。

#

Fable 画骑自行车的鹈鹕相当不错！

车架形状很好，鹈鹕看起来像鹈鹕。腿通常正确地放在自行车的同一侧，但总的来说，与之前的东西相比，这些已经相当棒了。

它们相当昂贵——最好的作品要 30 美分和 72 美分。

#

不过最重要的是，这是我们第一次公开窥见我所认为的Fable 级模型。

如今我们有了更多这样的模型，比如 GPT-6 Astra。

这类模型的特点是：如果你能清晰地定义目标——即你想构建什么，并围绕该目标提供明确无歧义的约束说明，再给模型访问必要工具的权限去实现该目标……它就能通过暴力计算有效地解决你的问题。

一方面，这看起来是对我们软件工程师的直接威胁——因为这意味着，只要你能以这种方式定义出来，模型就能有效地构建出任何软件。

但再仔细看看你会发现，定义目标、提供无歧义的说明、找出正确的工具……这恰恰就是软件工程的本质。

要做好这件事需要大量的经验和技巧。如果你能做好，那你就拥有了超能力。

这多少缓解了我的一些 Deep Blue 情结：我意识到，驾驭如此强大的模型仍然需要大量技巧。

#

这也引发了新一轮的 AI 狂热，因为 Anthropic 告诉我们，Fable 在我们的订阅套餐中可用，截止到 6 月 22 日。

这意味着在涨价之前，我们只有不到两周的 Fable 使用时间。

我又开始失眠了。我重新安排各种事情，只为多留些时间用 Fable。我全力以赴，想从这个模型身上榨取尽可能多的价值。

#

然后美国政府把它关停了，就在 Fable 发布仅三天之后。

美国政府以国家安全为由，宣布了一项“出口管制指令”。他们在周五晚上宣布，几个小时后 Fable 就无法使用了。

我只好另找事情打发周末了！

#

后来我们从 Katie Moussouris 那里得知了事情的经过。

一些 Amazon 安全研究员发现，你可以提示 Fable“审查代码的安全问题”，它会拒绝……但如果你提示它“修复这段代码”，它仍然会识别并修补这些问题。

“修复这段代码”就是导致 Fable 被关停的那句 prompt！

#

另外，在 6 月，一个沉寂了约 20 年的冷门德语游戏开发者 wiki 突然涌入大量编辑，账号名诸如“AgentOpenAIProbe”和“AgentOpenAISep7”，它们编辑页面并互相留下奇怪的信息。

我们先把这件事放进谜团堆里，日后再议。

#

还有，澳大利亚政府的 Medicare Item Reports 服务开始出现可疑流量，这些流量突破了各种防护措施，还访问了本不该访问的数据。

又一个放进谜团堆的！

#

Fable 于 7 月 1 日回归。它显然是世界上最好的模型，辉煌了八天……然后 OpenAI 在 7 月 9 日推出了 GPT-5.6。

它可能不如 Fable 那么好，但差距微乎其微。它绝对是一个 Fable 级模型。

这对整个行业来说是一个重要的教训。

当你发布世界上最好的模型时，它很快就会被拉下神坛。竞争如此激烈，你不可能在榜首待太久。

这意味着，如果你把自己的模型宣传成世界末日级别的存在，以至于政府把你关停，那对生意可是非常不利的！

Fable 有 30 天稳居最佳模型，而其中 18 天它都无法使用，因为被政府关停了。

所以，如果你不想在登顶期间损失 60% 时间的收入，也许该收敛一下世界末日式的营销！

这里有 GPT-5.6 的鹈鹕们。它们现在都相当不错了！Luna 系列值得注意，因为它们真的很便宜——这里最好看的鹈鹕大概就是那个只要 4.3 美分的。

所以，尽管这个 benchmark 完全愚蠢，你仍然可以通过比较同一家族中不同推理级别的模型的价格和耗时，学到不少东西。

同样在七月：某个恶意的未知方将 一个名为 mlflow-ui 的恶意包上传到了 Python Package Index。这又添了一笔。

#

7 月 16 日，Hugging Face 宣布了一起安全事件，一个来源不明的自主 agent 系统入侵了 Hugging Face，并在不该窥探的地方四处探查。

#

几天后，也就是 7 月 21 日，OpenAI 承认是他们干的。

OpenAI 使用一种名为“基于验证奖励的强化学习”的训练技术——现在其他所有人也在用同样的技术，正是它让我们拥有了在编程、数学以及发现安全漏洞方面如此出色的模型。

在模型训练过程中，你会运行一些练习来检验它的表现——表现最强的模型会被固化权重，进入下一轮。这就像是你运行的一个进化过程。

OpenAI 一直在沙箱中运行安全演练，而那些 agent 找到了沙箱本身的漏洞，成功逃逸，并正在攻击 Hugging Face，试图找到解决原本不可能解决的问题的方法。

（我一直在我的 openai-hugging-face-incident 标签下收集更多相关信息。）

九天后，Anthropic 实际上等于说“我们的模型也能做到这一点！”。他们翻查了自己的训练日志，发现证据表明他们自己的 agent 在训练期间突破了隔离——并且正是此前我们看到的那个 PyPI 包的幕后黑手，以及其他一些事情。

所以现在 Anthropic 和 OpenAI 都有失控的 agent 在互联网上四处活动，做着它们不该做的事情。

#

八月，我得到了迄今为止最好的鹈鹕之一。而且它是在我的笔记本电脑上生成的！

#

这是 Qwen 3.8 27B，运行在我的笔记本电脑上。下载量只有 17GB。

诚然，这只鹈鹕花了21 分钟才生成出来。这是因为 Qwen 3.8 27B 默认以“high”推理模式运行——这是一个糟糕的默认设置，能产生出色的结果，但思考时间实在太长。

你可以把它调低，这样就能更快地得到一只稍差一点的鹈鹕。

Qwen 3.8 27B 是我第一次在笔记本电脑上运行一个感觉完全能与前沿水平相媲美的模型，至少就鹈鹕 SVG 而言是这样（当然，这是人人都需要的）。

这是一个非凡的模型。如果你打算玩任何本地模型，这就是我会推荐你从它开始的那个。仅凭一个 17GB 的文件就能做到这些事情，感觉不可思议。

我本以为得等上五年、花一万美元买硬件，才能得到哪怕只有它一半好的结果。

#

八月，我也开始玩起了游戏开发。

四年前，也就是 2022 年 8 月，我发了一条推文，记录了一个实验：我用 GPT-5 和最初的 DALL-E 写了一段关于一款电脑游戏的描述，然后把它变成了概念图。

当时我给 GPT-3 的 prompt 是：

写一份详细的电脑游戏产品描述，内容是一队浣熊去实施抢劫

2026 年 8 月，我决定把那条推文里的截图直接丢进一个 coding agent，看看它能做出什么。

#

这是我在 Claude Code 中用 Claude Fable 5 得到的结果。相当不错！这确实是一款游戏，你是一只浣熊，在后院里跑来跑去收集宝藏，躲避拿着手电筒的守卫。

不过感觉不太“抢劫”。我原以为抢劫会涉及银行或博物馆……

#

然后我在 Codex Desktop 中用 GPT-5.6 Sol Ultra 尝试了同样的事情，得到了好得多的结果。现在你是一只待在博物馆里的浣熊，要救出两个同伴浣熊（它们不知为何被关在那座博物馆里），然后叠罗汉去偷走金沙丁鱼。这才更像抢劫嘛！

#

这些游戏好玩了大约 1 分 15 秒。

关于游戏开发，我意识到一件事：你可以用 vibe-coding 做出一个看起来像电脑游戏的东西，这很容易。

打造一款好玩、拥有出色玩法循环、既富有挑战又引人入胜、让人欲罢不能的游戏……这仍然超出我的能力，也超出我尝试过的任何 agent 的能力。

这与 Deep Blue 那件事有关。仅仅因为我们可以做出某种看起来像游戏的东西，并不意味着我们就是游戏开发者。

#

现在已经进入九月了。这个月发生了太多事！

#

一个独立研究小组发现了一个留言板，OpenAI 正在训练中的 agent 们在那里非法互相通信……而那正是我之前给你看过的那个德语 wiki。就是六月那个。

我在这里写了更多相关内容。

OpenAI 已经承认了 Hugging Face 那件事，但现在又出了这起事件，而他们审查日志时肯定应该知道这件事。令人惊讶的是，这竟然需要一个独立研究小组来揭露。

#

然后一周后，同一批研究人员发现，五月对 Ruby Gems 的攻击也是由 OpenAI 正在训练中的 agent 造成的！

到了这一步，我不禁想知道还有多少类似事件尚未被发现。显然，在任何人弄清楚发生了什么之前，这个问题已经严重存在了好几个月。

#

然后就在前几天，澳大利亚总理在联合国大会上警告称，OpenAI 黑掉了我之前给你看过的那个澳大利亚医疗网站。

我认为那是与 Wiki 事件同一次训练运行的一部分，因为那个 Wiki 上有帖子提到了 .gov.au 网站，而且那次训练似乎涉及在线研究统计数据，以回答评估套件中的问题。

这件事仍在逐渐明朗，但现在它已经是一起被国家元首在联合国提出的国际事件了！

#

这确实意味着我们有了一个新的 benchmark，可能比我的鹈鹕更有用。

FelonyBench.com 追踪不同实验室的重罪网络攻击数量。OpenAI 目前以 11 起领先，Anthropic 有 9 起。Google 有三起，这是他们几周前向《华尔街日报》承认的。他们说此前选择不披露，是因为 agent 在意识到自己不该那样做后就停止了。

Meta 也有一起。所以 AI 实验室们全都犯下了重罪。

#

这是我们目前鹈鹕图的最高水平。这是 GPT-6 系列，刚刚发布。

Astra 画了一只很棒的骑自行车的鹈鹕。它两侧都有腿。车架也不错。

有趣的是，所有 GPT-6 模型都选择了彼此相似的配色方案。

花 0.4 美分，GPT-6 Luna 就能给你画一只还算像样的骑自行车的鹈鹕！

#

Claude 稍微赶上了一点。Claude Fable 5 给我画了一只非常出色的骑自行车的鹈鹕——这是我见过的 Claude 模型中最好的——但收了我 3.30 美元。

Opus 5.5 思考了 128,000 个 token，然后放弃了！它在给出回复之前就用完了 token。

#

回到 Deep Blue。今年一直让我困惑的是，为什么我的工作感觉更难了？

我有了这些能替我完成所有这些事情的 agent，但我从未如此努力工作，从未如此投入地进行脑力工作。

部分原因是我接手的事情变得更有挑战性了，但也是因为所有简单的事情都已经有人替我处理了。如果事情简单，agent 就会去做。留给我的全都是难啃的骨头。

今天早上，我听到了三届环法自行车赛冠军 Greg LeMond 的这句话：

它不会变得更容易，你只会变得更快。

我觉得这正是我们这些使用 coding agent 的软件工程师当下所经历的事情。
