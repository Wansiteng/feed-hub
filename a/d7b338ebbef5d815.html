用 LFM2.5-24B-A2B 在设备端运行快速、私密的 agent

评分 8/10：本地端侧 agent 模型，契合本地推理与 agent 兴趣
原标题：Run fast, private agents on-device with LFM2.5-24B-A2B

要点

  • LFM2.5-24B-A2B 是 24B 参数、仅 2B 激活参数的端侧推理模型，支持工具调用与多步任务
  • 在 LiveClaw 上得分 48.09，超过 Qwen3.6-35B-A3B 的 38.19
  • 在 Apple M5 Max 上解码速度 184 tok/s，单张 NVIDIA B300 GPU 高并发下输出超 21K tok/s

LFM2.5-24B-A2B 是一个 240 亿参数的推理模型，仅有 20 亿活跃参数，专为在设备上运行快速、私密的 agent 而打造。它先思考再作答，能调用工具，并可在主流 agent harness 中完成多步任务。由于每个 token 仅激活 20 亿参数，每个推理 token 的成本都很低，因此你可以在自己的硬件上持续运行 agent。

  • 同类最佳 agent：在 agentic 和工具使用任务上与 Qwen3.6-35B-A3B 不相上下，而后者总参数和活跃参数均多出约 50%，在 LiveClaw 上得分为 48.09，后者为 38.19。
  • 以 MoE 速度推理：始终先思考再作答。每个 token 仅激活 20 亿参数，每个推理 token 的成本都很低。
  • 高效推理：在 Apple M5 Max 上达到 184 tok/s，在单块 NVIDIA B300 GPU 上输出最高可达 21K tok/s。

我们如何用 20 亿活跃参数构建一个推理 agent

LFM2.5-24B-A2B 基于 LFM2-24B-A2B 构建，并沿用了其架构：40 层、每个 MoE 块 64 个专家、top-4 路由，以及门控短卷积与 GQA 的相同混合结构。上下文窗口从 32K 扩展到 131K token，并通过原地 tokenizer 扩展将词表从 65K 翻倍至 128K token，以改善非拉丁语系的 tokenization。与前代不同，它是一个纯推理模型，在给出最终答案前会生成显式的思维链。

预训练规模从约 17T token 扩大到约 33T token。随后中期训练在 32K 上下文下加入 2T token，侧重推理、数学、代码、指令遵循和多语言文本，并在 131K 上下文下加入 300B token，侧重长上下文数据。工具调用和多轮轨迹贯穿这两个阶段。后训练通过五个阶段将基础模型转变为 agent：

  1. 监督微调（SFT）
  2. 教师专业化
  3. 多领域同策略蒸馏（MOPD），非 agentic：在非 agentic 任务上蒸馏专业化教师模型。
  4. MOPD，agentic：第二个蒸馏阶段，聚焦 agentic 任务。
  5. Agentic 强化学习（Agentic RL）：在 agent harness 中训练模型，例如 OpenClaw、Hermes Agent、Pi 和 OpenCode。

对于你的应用而言，其优势在于工具使用和指令遵循。LFM2.5-24B-A2B 在八项工具使用和 agentic 基准测试中的五项（AutomationBench、BFCLv4、ToolSandbox、LiveClaw 和 τ³-Bench Banking）上领先或与竞争对手持平，并且在 AutomationBench 上的得分是第二名模型的三倍多。它还在全部三项指令遵循基准测试中领先。更大的模型在 GPQA Diamond、HLE 和 AA-Omniscience 等知识密集型基准测试，以及 SWE-Bench Verified (OpenCode) 和 SciCode 等编程基准测试上仍占优势，因此对于知识密集型工作负载，请将 LFM2.5-24B-A2B 与检索或网络搜索搭配使用。

这些结果使 LFM2.5-24B-A2B 成为需要推理、调用工具并在你的设备上稳定运行的 agent 的坚实基础。

CPU 和 GPU 上的推理速度

LFM2.5-24B-A2B 从发布首日即获得整个推理生态的支持，包括 llama.cpp、MLX、vLLM、SGLang 和 ONNX。

边缘推理。LFM2.5-24B-A2B 是所对比的 MoE 中最快的，在 M5 Max 上解码速度达 184 tokens/s，在 Ryzen AI Max+ 395 上达 114 tokens/s。这比第二好的模型快至多 1.7 倍，同时占用内存最少。

GPU 推理。LFM2.5-24B-A2B 是同尺寸级别中最快的模型，在单块 B300 上高并发时输出速度超过每秒 21K tokens。

如何使用 LFM2.5-24B-A2B

当你需要能在你的设备上推理、调用工具并稳定运行的 agent 时，就选 LFM2.5-24B-A2B。

安装最新版本的 transformers（兼容 transformers>=5.0.0）：

pip install -U transformers

然后加载并运行模型：

from transformers import AutoModelForCausalLM, AutoTokenizer, TextStreamer

model_id = "LiquidAI/LFM2.5-24B-A2B"
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    device_map="auto",
    dtype="bfloat16",
#   attn_implementation="flash_attention_2" <- uncomment on compatible GPU
)
tokenizer = AutoTokenizer.from_pretrained(model_id)
streamer = TextStreamer(tokenizer, skip_prompt=True, skip_special_tokens=True)

prompt = "What is C. elegans?"

input_ids = tokenizer.apply_chat_template(
    [{"role": "user", "content": prompt}],
    add_generation_prompt=True,
    return_tensors="pt",
    tokenize=True,
)["input_ids"].to(model.device)

output = model.generate(
    input_ids,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.05,
    max_new_tokens=512,
    streamer=streamer,
)

在你的 agent harness 中使用

在本地以任意 OpenAI 兼容后端部署 LFM2.5-24B-A2B，然后将你的 agent harness 指向它。例如，使用 Hermes Agent：

hermes config set model.provider custom
hermes config set model.base_url http://localhost:8080/v1
hermes config set model.default LFM2.5-24B-A2B
hermes config set model.context_length 131072
hermes config set model.api_mode chat_completions
hermes config set agent.tool_use_enforcement true

端口取决于你的服务后端：llama.cpp 和 MLX 使用 8080，vLLM 使用 8000，SGLang 使用 30000，LM Studio 使用 1234。OpenClaw 和 Pi 的配置请参见模型卡，完整设置请参见我们的指南。视频示例请查看我们的发布博客。
