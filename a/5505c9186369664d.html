Holo4：驱动通用计算机使用 agent

评分 7/10：通用 computer-use agent 新模型发布，与 agent harness 兴趣直接相关
原标题：Holo4: powering generalist computer-use agents

要点

  • Holo4 发布 27B dense 和 35B-A3B MoE 两个版本，已上线 H Models API
  • Holo4 支持 GUI、代码、MCP 和 API 多种接口，同一模型跨桌面、网页、Android 运行
  • 在 OSWorld 2.0 上 Holo4 27B 得分 61.7%，Opus 5.5 为 81.8%，35B-A3B 为 30.9%

Holo4 是我们全新的 agentic 模型系列。它有两种规格：27B dense 和 35B-A3B Mixture of Experts。两者均可在 H Models API 上使用。我们同时发布 Holotron 3 的更新版本：Holotron4 Nano。

Holo4 建立在我们此前的模型之上，可通过任何可用的界面与软件交互：GUI、代码、MCP 和 API。它在学术 benchmark 上得分不错，但我们是专为真实业务工作流打造的。它通过监督学习和强化学习，在大量环境和任务上训练而成，其中包括由我们的 Agentic Task Factory 生成的任务。

立即开始使用：

为每一种界面打造的模型

Holo4 能在屏幕上点击和输入，能编写并运行自己的代码，也能调用 MCP 或 API 工具。它会选择最适合任务的方式。大多数 agentic 模型只针对单一界面训练：以 GUI 为重点的模型离开屏幕就寸步难行，而偏好工具调用的模型则困在没有 API 的应用面前。真实工作并非如此割裂，单个业务任务就可能需要结合这些不同方式。

Holo4 可运行在桌面、网页、Android、代码沙箱以及业务 API 上。每种情况下都是同一个模型，调用方式也相同。你无需为每个平台选择不同的模型。

Holo4 模型相比其 Qwen 基座有显著提升。在长工作流上，Holo4 仅落后于最强的闭源模型：在 OSWorld 2.0 上，Holo4 27B 得分为 61.7%，而 Opus 5.5 为 81.8%，Holo4 35B-A3B 则达到 30.9%。但它的参数量少了几个数量级，成本也低得多。我们将公开 benchmark 上得分背后的每一条 trajectory：可在 trajectories.hcompany.ai 回放每一步，或从 Hugging Face 下载。

以极低成本比肩前沿

在桌面控制（OSWorld 2.0）和 API 使用（AutomationBench）最难的学术 benchmark 上，Holo4 以远低于前沿模型的单任务成本与之竞争。

真正干活的 AI

基于我们 Agentic Task Factory 的环境和任务训练，Holo4 模型在专业软件上表现出色。以下示例展示了 Holo4 27B 与其基座模型 Qwen3.8 27B 的对比。两个模型使用相同的 prompt 和 harness。

3D 建模 · 埃菲尔铁塔

在 FreeCAD 中构建一个埃菲尔铁塔的 3D 模型，比例为 1 毫米比 1 米，以原点为中心并与 X 轴和 Y 轴对齐。按此设计进行制作。

该塔在任意高度上的平面均为正方形，绝不为圆形。其半宽，即从中心轴量到角点的距离，在地面处为 62.5 毫米，在高度 57 处为 32.5 毫米，在高度 115 处为 17.5 毫米，在高度 276 处为 9.35 毫米。在这些高度之间，半宽遵循一条平滑曲线，靠近地面处下降陡峭，越高处越平缓，绝不为直线。

四条相同的塔腿，每个象限一条，每条都是一个方形柱，其外角遵循该轮廓。每条塔腿在地面处宽 14 毫米，到高度 276 处收窄至 4 毫米。塔腿从地面到第一层平台之间彼此分离，并随着升高而收拢。它们之间不填充任何东西：塔是通透的，从任何一侧都能直接看穿。

三层平台，每层都是以中心轴为中心的实心方形板：在高度 57 处宽 72 毫米、厚 4 毫米；在高度 115 处宽 40 毫米、厚 3 毫米；在高度 276 处宽 22 毫米、厚 3 毫米。

一根从高度 276 到 324 的桅杆，方形，底部宽 8 毫米，向顶端收窄至 2 毫米。

每个部件都必须是体积非零的封闭实体，且任何部件都不得填充塔腿之间的空间。

Holo4 27B（84 次调用，130 万 token）

Qwen3.8 27B（60 次调用，100 万 token）

3D 建模 · H 标志

在 FreeCAD 中构建 H 公司标志的 3D 模型：一个实心填充的圆盘，旁边是一个块状无衬线大写字母 H，两者拉伸至相同厚度，两个形状高度相近且彼此分开、互不重叠，圆盘的中心与 H 的中部齐平。将两个形状都涂成黑色。

Qwen3.8 27B（118 次调用，190 万 token）

游戏设计 · Pac-Man

在 Godot 中构建一个 Pac-Man 风格的游戏，并让它保持运行。

一个由墙壁构成的矩形迷宫，按网格布局，豆子填满每一条开放的通道。一个玩家标记沿通道持续移动，吃掉经过的每颗豆子并为其得一分。三个幽灵在同一条通道中移动并追逐玩家。如果幽灵抓到玩家，玩家失去一条命，一切重置到起始位置。分数和生命值绘制在屏幕上。

没有人会来玩这个。玩家用简单的启发式自行驱动：在每个路口它朝最近的豆子前进，除非有幽灵靠近，此时它会远离幽灵移动。游戏必须无人值守地无限运行，完全不需要键盘输入。

当它正常工作时，启动游戏并让它一直运行。

Holo4 27B（68 次调用，240 万 token，268 行）

Qwen3.8 27B（197 次调用，1140 万 token，327 行）

我们如何构建 Holo4

Agentic Task Factory

我们内部的 agentic 流水线集合仅凭文档就能构建交互式环境和可验证任务，例如真实网站或开源软件的截图。到目前为止，它已在 Web 应用、MCP 服务器和桌面环境中产出了约 10,000 个任务，包括通过 GUI 和 MCP 暴露同一状态的混合环境。

训练

Harness

除了训练之外，我们还借助 OSWorld 2.0 上 agentic 性能的反馈，重建了我们的 harness——即执行模型动作并在数百步中管理其上下文的循环。Agents 会标记每个任务失败的原因，工程师则审查相应的修复方案。最大的改动是赋予 agent 一个可靠的记忆，使其能够跟踪数百步，并在桌面机器本身上提供一个 shell。

Opus 5（70.2%）和 GPT-5.6 Sol（66.2%）在 OpenAI 的发布图表中 v2026.08.08 离线集上使用了最大努力的部分奖励，与成本-性能图一致。其他参考分数来自模型卡和官方排行榜。任务发布、子集和 harness 各不相同。

Holotron4 Nano

我们的后训练技术栈旨在适应新的基础模型，并产出能够跨界面和环境泛化的 agents。作为 NVIDIA Nemotron Coalition 的成员，我们将最新的技术栈应用于 Nemotron 3 Nano Omni 模型，作为 Holotron 3 的后续工作。

同样的配方将 Nemotron 3 Nano Omni 转变为 Holotron4 Nano，这是一个通用 agentic 模型，在 GUI 工作流以及暴露 MCP、API 或编码沙箱的环境中显著优于基础模型。

增益是相对于 Nemotron 3 Nano Omni 的绝对百分点提升。

这些增益表明我们的配方具有良好的迁移性，能够将通用模型转变为 agentic 专家。其中没有任何内容是与规模相关的。
