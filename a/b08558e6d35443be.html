Synopsys 推出 Autopilot 平台，用 AI 自主开发芯片

Tom's Hardware · 评分 7/10：Synopsys 发布七个 AgentEngineer agent 平台，agent 工具链实质进展
原标题：Synopsys debuts Autopilot platform for developing chips autonomously using AI

要点

  • Synopsys 发布 Autopilot 平台与 AgentEngineer 智能体产品线
  • 平台覆盖验证、实现、AMS 设计、制造等六大领域
  • 已有超过 50 家客户参与，计划 2026 年底正式商用

Synopsys 发布了其 AgentEngineer 解决方案，这是一套基于其全新 Autopilot 平台构建的“领域专用长时程 agent”产品组合。正如该公司在一篇博客文章中详细介绍的那样，该产品组合涵盖六个命名领域：验证、系统验证、实现、模拟与混合信号（AMS）设计、制造，以及仿真与分析。据该公司称，已有 50 多个客户合作项目正在进行中，Synopsys 向 Tom's Hardware Premium 确认，计划于 2026 年底全面上市。此前在 7 月，该公司曾在设计自动化大会 DAC 上展示了与 Nvidia 和 Microsoft 合作开发的 agentic AI 工作流。

此次发布通过一条命名产品线和目标日期，让 Synopsys 的计划更加清晰。该平台的 agent 命名明确、界限分明，合作数量表明客户兴趣浓厚，而全面上市的目标则为生产环境中的自主 agent 锚定了路线图。两个头条性能数据是 7 月数据的重述，唯一具名的客户数据来自一家公司的范围。虽然 Synopsys 将这些 agent 描述为自主的，但该公司表示，审批检查点仍由人类掌控。

对于设计和生产芯片、希望利用 AI 潜在效率提升的公司来说，这项技术使他们能够“加速从AI 辅助设计向自主工程的转变”，Synopsys 首席产品管理官 Ravi Subramanian 表示。

Synopsys AgentEngineer 产品组合

  • 验证
    覆盖范围：从规范解读到覆盖率收敛 · 任务 agent：覆盖率收敛 · 工具层：仿真、模拟、调试
  • 实现
    覆盖范围：从布局规划、布局、布线、拥塞、DFT，到时序、功耗和设计规则收敛直至签核 · 任务 agent：PPA 收敛 · 工具层：RTL 到 GDS
  • AMS
    覆盖范围：模拟与混合信号设计、版图综合、IP 节点迁移、物理验证，以及晶体管级时序与表征 · 任务 agent：模拟设计 · 工具层：SPICE、版图
  • 制造
    覆盖范围：工艺与器件仿真、掩模综合，以及掩模数据准备 · 任务 agent：掩模综合 · 工具层：掩模、TCAD
  • 网格划分
    覆盖范围：生成、验证、修复和优化仿真网格 · 任务 agent：FEA 编码 · 工具层：结构分析
  • Blaze
    覆盖范围：燃气轮机燃烧研究及其仿真工作流 · 任务 agent：CFD 编码 · 工具层：流体仿真
  • EMC
    覆盖范围：PCB EMI/EMC 分析、对照 EMC 限值的辐射发射检查，以及设计迭代 · 任务 agent：EM 编码 · 工具层：电子仿真
  • 客户 agent
    覆盖范围：客户构建或引入的 agent，与 Synopsys 自有 agent 并行运行 · 任务 agent：— · 工具层：Synopsys 工具

在随发布一同发表的博客文章中，Synopsys 产品管理执行总监 Anand Thiruvengadam 详细介绍了三个层次：长时程 AgentEngineer 是“编排任务 agent 的领域专用超级 agent”，任务 agent“完成特定的、有边界的工程任务”，可由 AgentEngineer 编排，也可由工程师直接调用，而工具层的引擎“执行所请求的工作”，但不设定目标或做出决策。与可能连续数小时或数天执行单一活动的长时间运行 agent 不同，长时程 agent 解决的是“目标复杂性”，追求可能需要数百或数千个推理步骤的目标。

该平台覆盖了从编排到遥测的所有环节，并由一个“认知模型”驱动 Synopsys 所称的上下文智能。访问控制、加密和运行时护栏保护客户、合作伙伴和 Synopsys 的知识产权，这在第三方 agent 共享工作流时尤为重要。客户可以选择商用、开源或微调的语言模型，并部署在 Synopsys Cloud、自有云或本地基础设施上。换句话说，客户可以“自带 LLM、数据和基础设施”，Thiruvengadam 告诉 Tom's Hardware Premium。

博客概述了验证循环——agent 制定计划、编排任务 agent、检查它们返回的结果，并在中间结果不达标时进行调整。当测试发现 bug 时，根因分析（RCA）agent 会读取日志、聚类错误、形成假设，并检查波形以确认。然后，agent 会“对 RTL 进行局部重写，以证明 bug 确实已被修复”，并生成 bug 修复清单。当中间结果偏离目标时，agent 会“纠正方向、适应、反应”，他说。

Synopsys 新闻稿中的性能数字令人兴奋：验证收敛速度提升高达 50 倍，覆盖率提高 20%，生产力提升 30%，token 效率提高 2 倍，延迟更低。50 倍和 20% 的数字并不新鲜。Synopsys 告诉 Tom's Hardware Premium，这些数据来自其 7 月与 Nvidia 的合作，是相对于其自身未使用 AgentEngineer 的验证工作流测得的。30% 的数字处于富士通报告的 10% 到 30% 范围的上限，该范围是针对其 RTL 代码生成。

这些生产力提升是“与人类专家原本会做或今天正在做的事情相比”来衡量的，Thiruvengadam 说。2 倍的 token 效率，意味着给定任务使用更少的 token，是客户报告的：一位未具名客户将 Synopsys 的 agent 与其基于商用 agentic harness 构建的自有 agent 进行了比较。延迟声明没有具体数字；新闻稿和博客部分归功于上下文智能，这表明等待模型调用的时间更少。

另一个有结果的合作是 AheadComputing，其验证副总裁 Alon Mahl 表示，Implementation AgentEngineer 帮助减少了从 RTL 交接至签核的手动工程工作量，但没有给出具体数字。Intel、联发科和三星也认可了这项技术。它们都没有给出硬性结果，但都支持这项技术，认为其前景广阔。今天的发布是产品组合和平台，没有生产细节。Synopsys 早在 2020 年推出的 AI 工具 DSO.ai 已通过 100 次生产流片，而新的 agent 仍在合作中。

这些 agent 的自主性如何？每家供应商都用自己的标准定义自主性，Synopsys 去年推出了其 L1 到 L5 框架。“L5 的最初愿景是完全自主执行。但不仅仅是完全自主执行，还有复杂性，”Thiruvengadam 告诉我们，将 L5 描述为在人类护栏内自主执行复杂工作流。“这就是想法，而这正是我们现在所处的位置。”Synopsys 确认，它将这些 agent 描述为 L5。Cadence 也在 6 月的 Computex 上声称其自己的标准达到 Level 5。

今年早些时候，Nvidia 首席科学家 Bill Dally 表示，AI 将一项原本需要 8 名工程师耗时 10 个月的任务——为 GPU 设计移植标准单元库——缩短到了一夜之间完成，但 Nvidia 距离让 AI 端到端设计一款新 GPU 仍有“很长的路要走”。

人类工程师仍在流程之中，但监督的程度各不相同。“护栏仍将由人类来定义，关键的审批检查点仍将由人类驱动，”Thiruvengadam 说。“我们的客户将不得不学会信任这些自主系统。”该博客还补充说，团队可以设置检查点，让人工检查结果、验证决策并重新引导工作流，然后随着信心增强“减少干预”。目前还没有任何厂商说明其 agent 何时会停止重试或升级给工程师。

Synopsys 表示这些能力已经具备；它的下一个目标是正式发布。外界将关注 Synopsys 能否在 2026 年底前实现正式发布，并在届时公布一家已投入生产的客户。Cadence 预计 Level 5 将在 2026 年下半年开放早期访问，Siemens 则承诺在即将发布的版本中提供自验证能力。产品已经存在并在客户手中运行，而如果这些加速效果能够在内部评估之外得到实现，尤其是得到独立测试的佐证，那么它们看起来极具前景。
