Third Moment Research 如何让 10000 个 agent 连续运行 36 小时以上

评分 7/10：长任务多 agent 编排的实测案例，契合 agent harness 兴趣
原标题：How Third Moment Research runs 10,000 agents for 36+ hours

要点

  • Third Moment Research 用 OpenAI 模型同时运行 1 万个 agent，单次调查持续 36-48 小时
  • Codex 将一年美股订单级数据的回测从约 3 小时缩短到约 3-5 分钟
  • GPT-6.1 Sol 因 token 效率最高成为团队使用最多的模型

每家公司都有自己的一套工作流程、工具、边缘情况和成功定义。 ⁠（在新窗口中打开）Third Moment Research⁠（在新窗口中打开）认为，最好的 agent 应该非常擅长这些具体工作，并且使用得越多，能力就越强。

该公司正围绕这一理念构建一个自我改进的 AI 系统，利用 OpenAI 的最新模型来理解 agent 的行为、识别反复出现的弱点，并针对这些问题自动创建数千个合成场景。团队利用这些场景来改进 agent，并在新问题出现时重复这一过程。

Codex、GPT‑6 Astra、GPT‑6 Sol 和 GPT‑6.1 Sol 为该系统的研究和计算工作提供支持，使 Third Moment 能够同时运行 10,000 个 agent，进行持续 36 到 48 小时的调查。该公司还使用 Daybreak 来测试 agent 工作环境的安全性。

“在单次会话中，GPT-6.1 Sol 能够在数天的计算过程中保持一条连贯的计算研究思路，而不会偏离主线。”

——Adam Khakhar，Third Moment Research 联合创始人

Third Moment 的早期应用之一是在量化金融领域，因为该领域的成功标准非常明确。这一领域为研究 agent 如何工作以及在哪里遇到困难提供了一个具体的场景。团队使用 Codex 来发现并解决研究环境中的问题。

在一个案例中，它使用 Codex 搭配 GPT‑5.6（当时最新的 GPT 模型），结合时间戳和代码库，分析了数千条记录的模拟轨迹（即 agent 的动作和环境的响应）。

Codex 发现了一个瓶颈：用一年的订单级美国股票数据对交易策略进行回测需要几个小时。在等待期间，agent 反复轮询完成状态，浪费了 token，并让状态检查填满了上下文。

在对回测进行性能分析并分析其输入和使用情况后，Codex 找到了一种缓存优化和一种内存打包技术。它试验了多种解决方案，并将修复部署到生产环境，将回测时间从大约 3 小时缩短到大约 3 到 5 分钟。这减少了 token 使用和上下文污染，为 agent 腾出更多 token 预算用于进一步实验。

Third Moment 为每个 agent 提供其完成特定工作所需的工具、信息和环境。对于量化研究，团队在 Dockerized 环境中运行默认的 Codex harness。Agent 会获得 1TB 的数据、文档，以及一个包含特征工程、GPU 支持的模型训练、交易策略和模拟模块的研究代码库。

GPT‑6 Astra、GPT‑6 Sol 和 GPT‑6.1 Sol 提供推理能力，而 Codex harness 为 agent 提供行动、制定计划、设定目标、生成子 agent 以及在工作持续进行时压缩上下文的工具。

为了解决 agent 在完成任务前就停止的问题，Third Moment 将 Codex 视为由 GPT‑6 Sol 或 GPT‑6.1 Sol 驱动的外层 harness 中的一个子 agent。当任务未完成时，外层 harness 会检查轨迹，并决定是重试、终止任务，还是升级给人工审核。

“Codex harness 极其通用，使其能够应用于许多不同的领域。”

——Adam Khakhar，Third Moment Research 联合创始人

在该研究环境中，agent 致力于改进由 Third Moment 工程师构建的基线交易系统。它们在历史数据上测试交易策略，评估某项改进是有意义的还是噪声，并利用每次结果来选择下一个实验。据 Adam 称，它们的工作改进了基线交易系统。

Adam 表示，在 GPT‑5.5 之前，模型只能执行用户指定的实验。借助 GPT‑5.5 和 GPT‑5.6，配合 Codex harness 工作的模型可以利用结果设计后续实验。如今有了 GPT‑6 Astra、GPT‑6 Sol 和 GPT‑6.1 Sol，agent 可以通过与子 agent 并行运行的数百个实验来调查根本原因。

这一进展帮助 agent 探索了团队未曾预料到的研究方向。在一次会话中，GPT‑6.1 Sol 识别出了非展示交易对某交易所的影响，这些交易在该交易所的成交量中占比高得出乎意料。“这是一个不明显的结果，我们的研究团队最初并未考虑到，”Adam 说。

Third Moment 在优化、机器学习系统和量化研究方面评估模型。它以最高推理设置测试前沿发布版本，评估其浏览代码仓库、编写高效代码和持续开展调查的能力。当前测试还包括 GPT‑6 Luna。

“鉴于其 token 效率，GPT-6.1 Sol 目前是我们使用最多的模型。它以最少的 token 完成任务，同时性能与 GPT-6 Astra 相近。”

—Jeffrey Yan，Third Moment Research 联合创始人

其中一项 benchmark 要求 agent 在保持输出的同时降低一个实时记分板服务的更新延迟。团队通过将专家手工编写的解决方案的平均运行时间除以模型解决方案在同一硬件上的平均运行时间（以正确性为前提）来衡量加速比。据 Adam 称，GPT‑6 Astra 带来的加速最大。

对于针对性工作，包括检查模拟系统中的特定安全弱点，团队使用 GPT‑5.6 Terra 等更高效的模型。对于深度研究，Adam 认为更强的推理能力可以证明更高的成本是合理的：“在量化金融领域，找到某个有趣信号的价值极高。”

在 10,000 个 agent 自主运行的情况下，Third Moment 需要一种方法来大规模测试其研究环境的安全性。团队使用 Daybreak 网络安全平台在模拟启动前自动完成这项测试。

这些测试检查 agent 是否可能突破其研究环境并访问更广泛的网络。“通过使用 Daybreak，我们能够让 agent 自己对模拟进行渗透测试，并测试其基础设施和安全性，”Adam 说。

“如果没有 Daybreak，我们就无法大规模自主开展这项测试。”

—Adam Khakhar，Third Moment Research 联合创始人

Third Moment 的雄心还延伸到企业每天所做的专业工作。对零售商而言，这可能意味着在库存短缺或供应商延迟时做出更好的供应链决策。对工程团队而言，这可能意味着在大型代码库中找出性能瓶颈。对文档繁重的企业而言，这可能意味着识别一份文档中的承诺与另一份文档中记录的结果不匹配之处。

基于 GPT‑6 Astra、GPT‑6 Sol 和 GPT‑6.1 Sol 的推理能力，Third Moment 计划从单个调查扩展到数十万个协作子 agent。其路线图要求用数万亿 token 支持由数十个相互依赖的实验组成的链条，目标是在新挑战出现时利用这项研究自主改进 agent。

对 Adam 来说，这将赋予人们更强的能力去塑造 agent 的学习和工作方式：“人类可以处于一个杠杆效应大得多的位置，他们可以思考如何做研究、优化研究本身，而不是亲自去做研究。”
